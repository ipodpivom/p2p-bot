# Личные таблицы нескольких пользователей

У каждого разрешённого Telegram ID своя Google-таблица. Два пользователя не могут быть назначены на одну таблицу. Скриншоты, черновики, подтверждения, /pending и /stats разделены по пользователям; /table показывает только собственную таблицу. Администратор сервера управляет подключениями и сервисным ключом.

Существующий владелец сохраняет свою таблицу из GOOGLE_SPREADSHEET_ID. Его ID остаётся первым в ALLOWED_TELEGRAM_IDS. Дополнительные подключения задаются переменной USER_SPREADSHEETS_JSON. Бот не предоставляет публичную команду перепривязки таблиц.

## Подключение человека

1. Человек пишет боту /id и сообщает администратору полученный числовой Telegram ID.
2. Создаёт собственную пустую Google-таблицу и выдаёт сервисному аккаунту бота роль «Редактор». Его адрес администратор берёт из client_email своего JSON-ключа. Другому пользователю сам ключ не передаётся.
3. Передаёт администратору ссылку на свою таблицу.
4. Администратор из папки проекта с настроенным .env выполняет:

```sh
npm run add-user -- 123456789 https://docs.google.com/spreadsheets/d/USER_SHEET_ID/edit --initialize
```

Команда создаёт отдельный чистый лист «P2P Учет» с заголовками и формулами. Другие листы сохраняются. Если лист с таким именем уже существует, проверяется его структура; несовместимый лист автоматически не перезаписывается. Для заранее подготовленного журнала флаг --initialize можно опустить.

5. Команда выводит JSON с привязками, например:

```json
{"123456789":"USER_SHEET_ID"}
```

Сохрани всю выведенную строку как значение USER_SPREADSHEETS_JSON в Render → Environment и выполни Deploy. Для подключения следующих людей перед запуском команды используй актуальное значение этой переменной в локальном .env: тогда существующие привязки войдут в новый результат. Ключи и реальные списки подключённых пользователей хранятся в настройках сервиса, а не в GitHub.

6. Пользователь пишет /start, затем /table, проверяет ссылку и отправляет свой скриншот.

Пример серверных настроек: ALLOWED_TELEGRAM_IDS содержит ID владельца, USER_SPREADSHEETS_JSON содержит дополнительные ID и их таблицы. Владелец также может иметь явную запись в JSON. При смене личной таблицы старые неподтверждённые черновики не будут автоматически записаны в новую: скриншот нужно отправить повторно.

Каждая таблица ведётся независимо. Общих операций или общей прибыли между пользователями нет. На бесплатном сервере изображения обрабатываются по очереди; пределы Render и Firestore остаются общими для всего бота.
